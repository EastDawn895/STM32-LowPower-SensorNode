# MPU6050 模块复习笔记

> 适用范围：从传感器原理到驱动、校准、滤波、双节拍调度的完整实现线。
> 对应代码：`Drivers/MPU6050/`、`Libs/Filter/`、`App/app.c`

## 1. 芯片里有什么

一颗 MPU6050 = 三个传感器 + 一片寄存器空间：

| 传感器 | 测什么 | 单位 | 静止平放读数 |
|---|---|---|---|
| 加速度计 | 合力加速度（**含重力**） | g | Z≈+1g，倾斜时按角度分解 |
| 陀螺仪 | **角速度**（不是角度！） | °/s | 理想为 0，实际有零偏 |
| 温度计 | 芯片内部温度 | ℃ | 环境温度附近 |

两个关键认知：
- **加速度计静止有读数**：支撑面一直在顶着它对抗重力，模长恒 ≈1g（不管姿态怎么变）。
- **陀螺输出的是角速度**，要积才能得到角度，而积分会把任何恒定误差随时间放大——
  这就是零偏必须校准的数学原因。

## 2. 寄存器模型与 I2C 传输

- 芯片对 MCU 就是一排**带编号的字节格子**（寄存器）：
  - 配置 = 上电往特定格子写特定值（一次）；
  - 取数 = 从 0x3B 起反复读（主循环）。
- `HAL_I2C_Mem_Read/Write` 的 "Mem" 就指这片寄存器空间。
  **返回值是状态码（HAL_OK/ERROR/TIMEOUT/BUSY），数据通过指针带回**——
  把返回值当数据用是本模块出现过的第一个 bug（WHO_AM_I 恒 0）。
- I2C 地址：7 位地址 0x68（AD0 接地）→ HAL 要传左移后的 `0x68<<1=0xD0`。
- 一次 14 字节读事务在总线上的样子：
  `S → 0xD0(写) → 0x3B(寄存器号) → Sr → 0xD1(读) → 14字节(每个带ACK) → P`

## 3. 驱动三件套（mpu6050.c）

### Init：四条写

| 寄存器 | 值 | 含义 |
|---|---|---|
| PWR_MGMT_1 (0x6B) | 0x00 | 唤醒（bit6=SLEEP，上电默认睡觉，不写永远读 0） |
| SMPLRT_DIV (0x19) | 0x00 | 内部输出率 1kHz |
| GYRO_CONFIG (0x1B) | 0x00 | 量程 ±250°/s → 131 LSB/(°/s) |
| ACCEL_CONFIG (0x1C) | 0x00 | 量程 ±2g → 16384 LSB/g |

量程与分辨率是跷跷板：16 位 ADC 固定，量程越大每个 LSB 代表的物理量越大、越粗。
131 和 16384 就是后面所有定点换算的分母。

### WHO_AM_I (0x75)

固定返回 0x68，最小成本的开机自检（总线通、芯片在、地址对，三者缺一即失败）。

### ReadData：14 字节突发读

- 内存排布固定：AX高AX低 AY高AY低 AZ高AZ低 T高T低 GX高GX低 ... GZ低。
- **大端**：`(buf[0]<<8) | buf[1]`；**(int16_t) 强转**补符号（0xFF38 → -200）。
- 一次读 14 字节而不是 7 次：省 6 轮 start/stop，且这 14 个值语义上属于同一时刻。
- 出口唯一：**所有下游（串口/OLED/滤波）都从 ReadData 拿已校准的数据**。

## 4. 零偏校准（MPU6050_CalibrateGyro）

信号模型：`读数 = 真实角速度 + 固定偏置 + 随机噪声`

- **噪声**每次独立、绕真值对称 → 取均值互相抵消（√N 收敛）；
- **偏置**每次相同 → 均值消不掉，但因此**可以被测出来**：静止时真实=0，
  所以"静止读数的均值"就是偏置本身；
- 偏置随温度慢漂 → 校准值非永久有效（当前方案：每次上电校一次）。

实现要点（每条都有原因）：
1. 200 个样本：单次噪声约 ±130 LSB，均值误差压到 ±9 LSB（≈0.07°/s），代价 0.8s；
2. 累加器用 **int32**：16 位 ×200 会爆；除法**放循环外只做一次**；
3. 两次读取间隔 `HAL_Delay(2)`：芯片 1kHz 输出率，读快了重复采同一份；
4. 应用偏置在 ReadData 出口，`int32 中转再转回 int16`（写意图，防重构踩坑）；
5. 校准期间必须静止（0.8 秒窗口），App_Init 里打印提示。

踩过的 bug：
- 循环里累加成了 **ax/ay/az**（加速度）——校的是陀螺，且加速度计静止基准是重力不是 0；
- `if (!ReadData(...))`：**HAL_OK==0，成功时 !返回值 为真** → 成败判反。
  状态码枚举永远显式比较，不当布尔用。

## 5. 滤波（Libs/Filter，纯算法模块）

为什么抖：热噪声（MEMS 结构被空气分子撞击 + 电路热噪声）、供电纹波、
真实微振动、偏置温度漂移。**偏置能减掉，抖动只能压缩。**

滑动平均（N=8）：
- 环形缓冲存最近 N 个样本，维护**滑动和**：`sum = sum − 最老 + 最新`（O(1)）；
- **idx 语义 = 下一个要写入的槽位**。满窗时它恰好指向最老样本——
  因为写指针绕环一圈刚好 N 步，写序=将来的覆盖序（天然 FIFO）；
- 预热期（count<N）分母用 count，不用 N；
- 满窗后 count 必须**钉死在 N**（语义：有效样本数不再增长）；
  "count 不会超界"是被这个条件维护出来的不变量，不是免费前提。

踩过的 bug（测试设计的活教材）：
- idx **先移后写** → 新样本覆盖了第二老的数据，buf 与 sum 失同步；
- **恒定输入掩盖这个 bug**（覆盖哪个槽都是同一个值），阶跃输入才现形
  → 这就是测试要多个场景的原因：稳态用例、动态用例、噪声用例各抓一类 bug；
- count 无条件 ++ → 输出阴跌，256 次后回绕除零
  （PC 上崩溃，Cortex-M3 上 UDIV/0 静默返回 0——**所以在 PC 上先测**）。

工程规则：模块不 include 任何 STM32 头文件 → 纯算法可在宿主机 gcc 单测
（`test_main.c` 不进固件构建，永远不进）。

## 6. 双节拍调度 + 邮箱（App 层）

```
100ms：读传感器 → 灌滤波器（只更新，不打印；失败则跳过，坏数据不进窗口）
1Hz  ：从邮箱取数 → 串口打印 raw+filtered 双列 → OLED → LED
```

- **每个节拍有自己的时基变量**（两个 if 共用一个 s_lastTick 会让 1Hz 永远饿死）；
- 跨节拍传数据用**文件级 static 邮箱**：100ms 层写，1Hz 层读；
- 验证数据（硬件实测）：静止 raw ±1.6°/s → 滤波后 ±0.7；甩动 raw 尖峰
  −373.8°/s 被压到 −41.9°/s（≈9 倍衰减 + 约 0.4s 滞后 = N/2×100ms 的窗口数学）；
- 滤波会吃掉短促尖峰 → 将来报警要同时看 raw 瞬时阈值和 filtered 趋势。

## 7. 坑合集（面试素材速查）

| 坑 | 教训 |
|---|---|
| HAL 返回值当数据用 | 状态码和数据走两条路 |
| `!` 判断状态码 | HAL_OK==0，成功是"假值"，必须显式比较 |
| uint8_t 循环变量配 uint16_t 上限 | 255 回绕死循环，编译器不报错 |
| 字模表定义在 .h | 二次 include 即重复定义；定义进 .c，extern 进 .h |
| 空循环延时 | GCC 优化后为零次；用 HAL_Delay |
| -O0 撑爆 64KB flash | Debug 构建统一 -Og，HAL 体积减 ~30% |
| 两节拍共享时基 | 每个任务自己的 tick 变量 |
| count 无界自增 | 不变量要靠代码主动维护 |
| idx 先移后写 | "写入位"与"最老位"先重合再分开 |

## 8. 定点数约定（全项目通用）

无 float（F103 无 FPU，printf 浮点撑爆 flash）：
- 物理量一律"放大 100 倍的整数"：`ax_100 = raw × 100 / 16384`；
- 显示用 `Debug_PrintFixed(val, decimals)`（整数当定点打印）；
- 例子：raw=-4897 → ×100/131 = -3738 → 打印 "-37.3"，即 -37.3°/s。
