# Flash v1格式与恢复规则

只使用地址0x0000～0x1FFF。每扇区4096 B：首32 B头部、127条32 B记录。所有多字节字段为小端，与C结构体布局无关。

| 偏移 | 头部（32 B） | 记录（32 B） |
|---|---|---|
| 0 | magic 0x534E4831 | magic 0x534E5231 |
| 4 | 扇区代际uint32 | 全局记录序号uint32 |
| 8 | 格式版本uint32=1 | HAL tick时间uint32（非实时时钟） |
| 12 | 扇区编号uint32=0或1 | 有符号数值的32位补码编码 |
| 16 | 保留，写0 | source uint8：1运动、2光照 |
| 17 | 保留，写0 | state uint8：对应源的状态枚举 |
| 18 | 保留，写0 | 版本uint8=1 |
| 19 | 保留，写0 | 保留，写0 |
| 20 | 保留uint32=0 | 所属扇区代际uint32 |
| 24 | CRC32 | CRC32 |
| 28 | 提交标记0x434D5431 | 提交标记0x434D5431 |

CRC32覆盖偏移0～23，反射多项式0xEDB88320，初值0xFFFFFFFF，最终取反。源1数值为经零偏修正的GX原始滤波计数，源2为ADC滤波计数；不是浮点物理量。

## 提交

确认目标槽已擦除后，Page Program写前28字节，等待完成；再单独编程末尾4字节，等待完成并读回比较32字节。每槽32字节对齐，因此不会跨256字节页；只在FF字节上做1→0编程。提交不是原子写保证：必须同时校验完整标记和CRC。

## 恢复与轮转

- 开机扫描两扇区全部槽；只接受有效头和匹配其代际的已提交、CRC正确记录。
- 游标位于最新头对应扇区内最后一个非空槽之后；坏槽/半写槽也占用空间，不能直接重写。
- 序号与代际使用模2^32新旧比较；两扇区头代际相等或正好差2^31时拒绝恢复。
- 若最新扇区满，只擦除另一扇区；逐块确认整个目标扇区为FF，再提交新代际头。最新已提交扇区在此期间不修改。
- 新头已提交但记录尚未提交时，重启继续使用该新扇区，序号从保留的有效记录恢复。
- 两扇区全空时可以建立新格式；两扇区无有效头但存在非空数据时禁用写入，保护旧格式/未知数据。
- 至少一个有效v1头证明本区域已由v1管理；此时另一损坏头扇区可在安全轮转时回收。不能将该规则解释为支持任意人工混合格式或任意位损坏恢复。
- SPI失败、读回不一致、擦除不完全或恢复歧义均停止日志写入，不做无限重试。

队列容量4；溢出与写失败可观测。提交结果不确定时Drop可能计入实际已经完成的记录，这是“未确认持久化”，不是对物理丢失数量的精确统计。复位后Drop重新计数。

测试模型在旧扇区擦除、头主体、头提交、记录主体、记录提交五处注入13种前缀长度中断，共65种轮转切断情形，检查最新扇区不被触及及重启后可继续。另测CRC损坏、未知格式、序号/代际回绕及多圈。模型不模拟所有真实Flash模拟电路效应，真实随机断电必须另验。

## 串口状态与现场诊断（2026-11-06）

- `Log=0`：LOGGER_READY，可以接收事件；不是已写入记录数，也不表示RAM队列已全部提交。
- `Log=1`：LOGGER_IO_ERROR，初始化读取或运行I/O/超时/验证失败；停止日志，排障后复位重新扫描。
- `Log=2`：LOGGER_FORMAT_ERROR，无有效头且区域非空，或两有效头代际相同/相差2^31；保护介质，不擦除、不写入。旧格式、损坏数据、第一次建头中途掉电都可能导致无有效头，具体原因必须读取介质判断。
- `Drop`：有效参数事件在日志不可用或4条队列满时，每次拒收加1；运行I/O失败时，加上队列中所有尚未确认持久化事件（含在途事件），清空该队列并置Log=1。非法API参数返回错误但不计入Drop。只在Init/复位重新计数，没有为消除告警而清零。
- 自动事件仅在有效样本对应状态进入ACTIVE或HIGH/LOW的边沿产生；稳定状态、回到IDLE/NORMAL不记事件。Log=2时仍统计被拒收的边沿，所以Drop会随异常进入增长；这表示事件确实没有被该日志器接收，不能当作记录成功。
- 队列满保持Log=0，读写失败置Log=1，格式保护置Log=2；当前Drop合并计数，不能单凭它区分每种原因，也不记录历史淘汰条数。
- `OLED=0/1/2/3` 对应HAL_OK/ERROR/BUSY/TIMEOUT，反映显示驱动最近的状态，不是屏幕内容或帧数的证明。

用户给出的Log=2、Drop在LOW进入时5→6且随后稳定，符合保护模式下拒收事件的设计。不能从这段日志判定Flash硬件损坏，也不能认定日志功能已验收通过。先备份外部Flash至少前8192字节，离线检查头/CRC/提交标记；确认不再需要旧数据后才人工初始化该区域。不要执行整片擦除来替代局部迁移。
